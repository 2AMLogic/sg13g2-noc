# verification

`run.sh` is the single entry point; it dispatches on its first argument
(`endpoints`, `endpoints-selftest`, `router`, `mesh`, `all`).
cocotb is never installed on the host: `run.sh` provisions it per run in a
throwaway `uvx` environment at the version pinned in `layout/tools.json`, and
refuses a mismatch with Icarus or cocotb. Icarus and Yosys are worker tools.

## Endpoints loopback (issue #19)

```
verification/run.sh endpoints                 # exit 0 = every run clean; writes endpoints/results.json
verification/run.sh endpoints --neg corrupt   # negative control: exits non-zero, names the check
verification/run.sh endpoints --neg skipseq
verification/run.sh endpoints-selftest        # both controls; exit 0 only if both trip
```

`endpoints/` holds `loopback.v` (generator -> link register -> checker, credit
back through its own register), the cocotb bench `test_endpoints.py` and the
driver `run_bench.py`. About 20 s end to end.

What it runs (all simulated, 64 packets per run):

- **Sweep**: 3 patterns x 7 rates (0.05 .. 1.0) x lengths 1, 4, 16, at node (0, 1)
  of a 2 x 2 mesh with `DEPTH` 4, plus rate 1.0 with a random-stall checker
  (`stall_max` 8).
- **Depth 1**: rate 1.0, every pattern and length, with and without stall.
- **Coordinates**: every node of a 2 x 2 and a 4 x 4 mesh, every pattern, so
  transpose and hotspot are exercised from all positions.

Scoreboard per run (`spec/noc.md` §5): no loss, no duplication, in order per
(src, dst), payload integrity (the checker's own flags), the generator log
equal to the head flits on the link, destinations inside the pattern, and drain
within `npkts * length * (stall_max + 4 + depth) + 1000` cycles after
injection ends. A watchdog fails the run if no flit is accepted for 400 cycles
after injection ends. 64 packets per node keeps every (src, dst) sequence
number far below the 65536 wrap.

`results.json` records, per run: pattern, rate, length, node, stall, depth,
packets sent and received, errors, drained, the drain bound, achieved offered
rate and latency (generation to last flit accepted, cycles, simulated). It is
regenerated by each run; commit a new one only as new evidence.

Not covered here: the router and the mesh top (see below); latency or throughput
through a network is measured by the mesh bench.

## Router (issue #18)

```
verification/run.sh router                       # DEPTH=4, then DEPTH=1; exit 0 = all pass
NEG=NEG_YX_TURN verification/run.sh router       # negative control, must exit 1
NEG=NEG_DROP_CREDIT verification/run.sh router   # negative control, must exit 1
```

Same cocotb provisioning as the endpoints bench (per-run `uvx` environment, no
venv in the repo).

## `router/`

`test_noc_router.py` drives `rtl/noc_router.v` in isolation at (X, Y) = (1, 1) of
a notional 4 x 4 mesh. The bench plays the tile edge: one link register per
direction (forward flit, reverse credit), so the credit round trip is the 4
cycles 0002 sizes depth 4 for. Sources obey credits; sinks buffer `DEPTH` flits
and return a credit when they consume, optionally with random bounded stalls.

Checks, named in every failure message:

- `[scoreboard]` (spec section 5): no loss, no duplication, in order per
  (source input, destination), payload and `last` intact (which also catches
  interleaving), packet leaves the output XY says, injected equals delivered.
- `[credit-conservation]`: every cycle, for all ten links, source/router credits +
  flits in flight or buffered + credits in flight = `DEPTH`.
- `[watchdog]`: no flit accepted at any output for 100 cycles while flits are in
  the system.
- `[drain]`: everything accepted within 200 + 4 x (max stall + 2) x (flits still
  in the network when injection ends) cycles.

Tests: a packet from every input to every output it can legally reach (1 and 4
flits); zero-load latency; back-to-back packets; two inputs contending for one
output; random legal traffic at rates 0.05 / 0.3 / 0.7 / 1.0 with lengths 1, 4,
16; the adversarial test (all five inputs, 16-flit packets, rate 1.0, random
sink stalls, then a four-neighbour hotspot to the local output); uncontended
throughput. `run.sh` runs the whole set at `DEPTH=4` and `DEPTH=1`.

Latency and throughput lines are labelled SIMULATED and carry their pattern,
length and DEPTH. In the packet header the source field `[27:24]` holds the
input port number here, standing in for the source node.

Not covered here: reset applied mid-traffic and the rate x length sweeps
(mesh/endpoint benches), and the watchdog has no negative control of its own
(the credit-drop control is caught first by the credit assertion).

## Mesh (issue #25)

```
verification/run.sh mesh                          # DEPTH=4 then DEPTH=1; exit 0 = every run clean; ~3.5 min
NEG=NEG_DROP_CREDIT verification/run.sh mesh      # negative control, must exit 1 and name the check
NEG=NEG_CORRUPT     verification/run.sh mesh
NEG=NEG_SKIPSEQ     verification/run.sh mesh
verification/run.sh all                           # every bench plus the mesh controls (item-9 cold start)
```

`mesh/` holds the cocotb bench `test_mesh.py` and the driver `run_bench.py`. The
DUT is the shipped `rtl/noc_mesh.v` (four tiles: router, generator, checker, edge
link registers), configuration broadcast to all four endpoints, 64 packets per
node per run, results in `mesh/results.json` (regenerated by each run; simulated).

Checks, named in every failure message (`spec/noc.md` section 5):

- `[scoreboard]`: every generated (src, dst, seq) arrives exactly once at its
  destination, in order per pair; the generation log is dense per pair; flit and
  packet totals match.
- `[checker]`: the endpoints' sticky flags (payload, sequence, destination, framing).
- `[pattern]`: transpose destinations, hotspot share near 0.5, never self.
- `[credit-conservation]`: for every tile-edge link and both endpoint ports, from
  register state, sender credits + flit in the router register + flit in the link
  register + receiver buffer + credit in the credit register = `DEPTH`. Checked
  every cycle in the adversarial, depth-1, reset and negative runs, every 16th
  cycle in the sweep (a lost or duplicated credit persists, so sampling catches it).
- `[watchdog]`: no flit accepted anywhere for 400 cycles while packets are outstanding.
- `[drain]`: all packets accepted within `total_flits * (stall_max + 4 + depth) + 1000`
  cycles after the last packet is generated.
- `[reset]`: reset applied mid-traffic really interrupted traffic, and leaves
  buffers, link registers and credit counters clean.

Runs (DEPTH=4): uniform / transpose / hotspot x rates 0.05 .. 1.0 x lengths 1, 4,
16; adversarial rate-1.0 runs (diagonal, transpose, uniform, hotspot; lengths 16 and
4; sink stalls up to 15); reset mid-traffic. DEPTH=1: hotspot at lengths 1, 4, 16
with and without stalls, plus diagonal, transpose and uniform with long packets;
reset mid-traffic.

The diagonal-opposite pattern (every node sends to the node across the mesh) is
not one of the generator's three patterns. The bench forces each generator's
`dst_id` net to the opposite node over VPI; no RTL is changed. Transpose covers
only the (1,0) <-> (0,1) pair, since the diagonal nodes idle.

Negative controls reuse the RTL `ifdef`s: `NEG_DROP_CREDIT` (router swallows a
credit; trips `[credit-conservation]`), `NEG_CORRUPT` (trips `[checker]`),
`NEG_SKIPSEQ` (trips `[checker]` and `[scoreboard]`). `NEG_YX_TURN` is not offered
here: in a 2 x 2 mesh no packet continues in Y after a Y hop, so the turn it injects
never occurs; the isolated router bench covers it.

## Item-9 inventory

`attest/item9.json` lists every bench behind a claimed number with its cold-start
command (`verification/run.sh all`) and the PDK and tool pins. Regenerate and check:

```
uvx --from "klayout-tools==$(cat .github/klt-version)" klt signoff --attest 9 --inventory attest/item9.json -o evidence/item9.json
uvx --from "klayout-tools==$(cat .github/klt-version)" klt signoff --attest 9 --inventory attest/item9.json --check evidence/item9.json
```

The cold start is `local_only` (CI has no Icarus or cocotb worker), so `--check`
carries its committed outcome and re-verifies the file hashes and pins.
